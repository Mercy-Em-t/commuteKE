Technical guidelines for connecting third-party location providers to Transy.

📡 Hardware Tracker Webhooks

If your Sacco uses physical vehicle trackers (e.g., Cartrack, Tramigo, Frotcom), you can forward telemetry data to Transy in real-time using webhooks.

Webhook Endpoint

POST https://commute.tmsavannah.com/api/v1/gps/hardware-webhook

Required Action:

Since every tracker provider formats their JSON payload differently, we require the API documentation for your specific provider. Once provided, we will map their payload schema to our ingestion engine.

Standard Payload Schema Mapping:

Regardless of the provider's format, their webhook must include the following minimum data points:

  • device_id or tracker UID (Matches the Tracker ID field in Fleet Management)
  • latitude and longitude
  • timestamp (ISO-8601 preferred)

🟢 Safaricom LBS (Cell Tower Triangulation)

For drivers without smartphones or hardware trackers, Transy can track locations using the driver's Safaricom SIM card via the Daraja Location Based Services (LBS) API.

Prerequisites

The Sacco must possess an approved Corporate Daraja account with LBS API access granted. The approval process requires KYC and data privacy compliance.

Implementation Details:

  • Polling Strategy: Transy polls the Daraja API on a 5-minute CRON schedule for all active trips configured to use SAFARICOM_LBS.
  • Opt-in Requirement: According to Kenyan Data Privacy regulations, the driver must explicitly consent to being tracked. They will receive a USSD prompt from Safaricom (e.g., *100#) to accept tracking requests from the Sacco.

📱 Driver Phone App (PWA)

The standard method uses the driver's smartphone GPS via the Transy Progressive Web App.

Client-Side Push Endpoint

POST /api/v1/dispatch/update

Requires the web app to be served over HTTPS and the driver must grant Location permissions to their browser.
